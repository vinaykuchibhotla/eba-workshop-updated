## Code Changes Required

### 1. Remove hardcoded credentials and insecure MySQL options *(Security — High Priority)*

**File**: `DatabaseInitializer.cs` — locate the `GetConnectionString` method (or equivalent):
- Remove or replace any hardcoded fallback username/password.
- Move credentials to .NET User Secrets (development) or environment variables (production).
- Change `SslMode=Disabled` to `SslMode=Required` (or at minimum `SslMode=Preferred`) once the target server supports TLS.
- Remove `AllowPublicKeyRetrieval=true` or restrict it to a development-only configuration block.

**File**: `appsettings.json`:
- Remove any plaintext password from the connection string value.
- Replace with an empty placeholder resolved at runtime from an environment variable or User Secrets:
```json
"ConnectionStrings": {
  "Default": "Server=localhost;Database=orchardlite;User=appuser;Password=;SslMode=Required;"
}
```
- Ensure `appsettings.json` is listed in `.gitignore` if it still contains credentials, or scrub it before the next commit.

### 2. Validate MySql.Data 26.10.0 connection string options

**Files**: `DatabaseInitializer.cs` and any location where `MySqlConnection`, `MySqlConnectionStringBuilder`, or `MySqlCommand` is constructed:
- `MySql.Data` 26.x (Connector/NET 9+) dropped or renamed several legacy keys. Confirm the following options still compile **and behave correctly at runtime**:
  - `AllowPublicKeyRetrieval`
  - `SslMode`
  - `ConnectionTimeout`
  - Any `MySqlCommand.CommandType` usage with stored procedures
- After starting the app against a real MySQL instance, watch for:
  - `MySqlException` on connection open (especially authentication errors)
  - `ArgumentException` or `InvalidOperationException` for unrecognized connection string keys
  - Driver deprecation warnings in application logs

### 3. Remove leftover backup and artifact files

Delete the following files from the repository (they serve no runtime purpose and will cause confusion in source control):
- `Program.cs.bak`
- `Startup.cs.bak`
- All files matching `PortSolutionResult.*`

### 4. Fix hardcoded port binding *(Deployment correctness)*

**File**: `Program.cs`:
- Remove or make conditional the hardcoded `UseUrls("http://+:80")` call.
- Prefer the `ASPNETCORE_URLS` environment variable so the binding can be overridden without a code change:
```csharp
// Remove: .UseUrls("http://+:80")
// Let Kestrel default to ASPNETCORE_URLS, or set it explicitly in the environment.
```
- Note: .NET 10 Kestrel defaults to port **8080** when running as a non-root user. Any infrastructure or health-check configuration targeting port 80 must be updated accordingly.

### 5. *(Optional)* Modernize hosting to .NET 10 minimal API style

**Files**: `Program.cs` and `Startup.cs`:
- The `Startup`-based pattern compiles and runs on .NET 10 but is considered legacy.
- Consider consolidating into a single `Program.cs` using `WebApplication.CreateBuilder` / `app.MapControllerRoute`.
- **This is not a blocker** — defer if not currently in scope.

## Deployment Considerations

- **Port binding**: Remove the hardcoded `UseUrls("http://+:80")` and rely on the `ASPNETCORE_URLS` environment variable. Update any reverse proxy, load balancer, or health-check configuration to match the actual listening port (default 8080 for non-root on .NET 10).
- **MySQL SSL**: Production MySQL servers require TLS. Changing `SslMode=Disabled` to `SslMode=Required` requires either the server certificate to be trusted by the host OS trust store or an explicit `SslCa=<path>` in the connection string.
- **Secrets management**: Confirm `appsettings.json` contains no plaintext credentials before committing or deploying. Use environment variables, .NET User Secrets (development), or a secrets manager (production) for all sensitive values.
- **MySQL driver compatibility**: Verify the production MySQL server version is supported by `MySql.Data` 26.10.0. Connector/NET 9+ has minimum server version requirements — consult the Oracle release notes for the exact floor version.

**What deploys:** web, worker and console projects. Class libraries and test projects are not deployed. WinForms and WPF apps can't run in Linux containers, so skip this step for them. A console app that runs once and exits deploys as an ECS task or a Kubernetes Job, not a long-running service.

Give the prompt below to your coding assistant (Kiro, Claude Code, or another MCP client). It uses the AWS Transform MCP server and the **Source Code Containerization** agent (`vmware-containerization-agent`). That agent builds the image, pushes it to Amazon ECR, generates Terraform or Helm, and deploys to **Amazon ECS or EKS**. For EC2, Elastic Beanstalk or Lambda, stop after Publish Images and deploy the ECR image yourself.

### Setup (once)
- Claude Code: `claude mcp add aws-transform -e AWS_PROFILE=<profile> -- uvx awslabs.aws-transform-mcp-server@latest`
- Kiro: add to `~/.kiro/settings/mcp.json`:
  `{"mcpServers":{"aws-transform":{"command":"uvx","args":["awslabs.aws-transform-mcp-server@latest"],"env":{"AWS_PROFILE":"<profile>"}}}}`
- `AWS_PROFILE` is optional. Without it, the assistant signs in with IAM Identity Center, which opens a browser.
