## Code Changes Required

### 1. Hard-coded `UseUrls` port — `Program.cs`
.NET 8+ official container base images listen on port **8080** by default and run as a non-root user; binding to port 80 will fail without elevated privileges.

- **File**: `Program.cs` (or wherever `UseUrls` is called)
- **Change**: Remove the hard-coded port and rely on environment-driven configuration:
  ```csharp
  // Before
  .UseUrls("http://0.0.0.0:80")

  // After — idiomatic .NET 8+ approach: remove UseUrls entirely and
  // set ASPNETCORE_URLS or ASPNETCORE_HTTP_PORTS via environment variable.
  // If an explicit fallback is needed:
  .UseUrls(Environment.GetEnvironmentVariable("ASPNETCORE_URLS") ?? "http://0.0.0.0:8080")
  ```

### 2. Hard-coded DB credential fallback — connection string source file
- **File**: whichever source file constructs the MySQL connection string (likely `Startup.cs`, `DatabaseInitializer.cs`, or a configuration helper)
- **Change**: Replace any hard-coded credential defaults with a startup-time exception to force explicit configuration:
  ```csharp
  // Before
  var password = Environment.GetEnvironmentVariable("DB_PASSWORD") ?? "hardcodedFallback";

  // After
  var password = Environment.GetEnvironmentVariable("DB_PASSWORD")
      ?? throw new InvalidOperationException(
             "DB_PASSWORD environment variable is required and was not set.");
  ```
  Apply the same pattern to `DB_USER`, `DB_HOST`, `DB_PORT`, and `DB_NAME` if any of those also have hard-coded fallbacks.

### 3. Plaintext credentials in `appsettings.json`
- **File**: `appsettings.json`
- **Change**: Remove any plaintext `DB_PASSWORD`, `DB_USER`, or full connection string values. Replace them with environment variable references or leave the keys empty and rely solely on environment variables at runtime.
- Locally, switch to `dotnet user-secrets` for developer credentials.
- Ensure `appsettings.json` (and `appsettings.*.json`) are listed in `.gitignore` if they ever contained real credentials, and confirm `.dockerignore` excludes them from the container image.

## Deployment Considerations

- **Port change**: The .NET 10 `aspnet` container base image defaults to port **8080**, not 80. Update any load balancer rules, Kubernetes `containerPort` / `Service` specs, or `docker run -p` mappings that previously targeted port 80.
- **Non-root container user**: .NET 8+ base images run as the built-in `app` user (UID 1654) by default. Review the Dockerfile for any steps that require root access (writing to `/etc`, binding to ports < 1024, etc.) and revise those steps accordingly.
- **`MySql.Data` 26.10.0 server compatibility**: Connector 26.x targets MySQL 8.x/9.x servers. If the target environment runs MySQL 5.7, additional testing is required and it may be necessary to pin to an older connector version or switch to `MySqlConnector` (the community-maintained alternative), which has broader version compatibility.
- **Secrets hygiene**: Confirm that `appsettings.json` files containing credentials are excluded from both source control (`.gitignore`) and container images (`.dockerignore`) before any deployment to a shared or production environment.

**What deploys:** web, worker and console projects. Class libraries and test projects are not deployed. WinForms and WPF apps can't run in Linux containers, so skip this step for them. A console app that runs once and exits deploys as an ECS task or a Kubernetes Job, not a long-running service.

Give the prompt below to your coding assistant (Kiro, Claude Code, or another MCP client). It uses the AWS Transform MCP server and the **Source Code Containerization** agent (`vmware-containerization-agent`). That agent builds the image, pushes it to Amazon ECR, generates Terraform or Helm, and deploys to **Amazon ECS or EKS**. For EC2, Elastic Beanstalk or Lambda, stop after Publish Images and deploy the ECR image yourself.

### Setup (once)
- Claude Code: `claude mcp add aws-transform -e AWS_PROFILE=<profile> -- uvx awslabs.aws-transform-mcp-server@latest`
- Kiro: add to `~/.kiro/settings/mcp.json`:
  `{"mcpServers":{"aws-transform":{"command":"uvx","args":["awslabs.aws-transform-mcp-server@latest"],"env":{"AWS_PROFILE":"<profile>"}}}}`
- `AWS_PROFILE` is optional. Without it, the assistant signs in with IAM Identity Center, which opens a browser.
